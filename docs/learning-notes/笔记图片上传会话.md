# 笔记图片上传会话

## 1. 背景与目标

### 1.1 背景

学习笔记编辑器基于 `RichEditor`（Tiptap），图片插入走 `onUploadImage` 回调：用户粘贴 / 拖放 / 工具栏选图后，由 `LearningNotesStore.uploadNoteImage` 调用 `NotesApi.uploadImage` 上传到 COS，再把 URL 插入正文。

直接上传会带来**孤儿图片**问题：

- 用户**上传图片 A**（已落 COS，正文里多了 `<img src=A>`）
- 用户**删掉图片 A**（正文里没了，但 COS 上的 A 仍在）
- 用户**未保存**或**切到另一篇笔记 / 关闭页面**

此时 COS 里就残留了一张没人引用的图。同样，「上传 → 删除 → 改回原样 → 保存」也会把刚上传的图丢在 COS 里没人认领。

### 1.2 目标

为「一次编辑会话」内的图片上传建立**会话（session）级 pending 追踪**，让服务端能在合适时机自动回收孤儿：

- **进入编辑/新建**：分配 `uploadSessionId`；本会话内上传的图统一记 pending。
- **保存**：把当前正文里的图「认领」给笔记，未被认领的 pending 全部回收。
- **内容回到基线（dirty 由 true → false）**：按当前正文结算一次，把「上传又删」的 pending 回收。
- **切笔记 / 新建**：直接 `discard` 当前会话，pending 全部回收。
- **刷新 / 关页**：用 `keepalive` fetch 兜底 `discard`，避免浏览器卸页时异步 Host http 被掐断。

## 3. 实现思路

### 3.1 会话生命周期

```
openNew / openEdit       ──► uploadSessionId = crypto.randomUUID()
       │                         │
       │  粘贴/拖放/选图          ▼
       │                   uploadNoteImage(file)
       │                         │
       │                   POST /upload-image (带 sid)
       │                         │
       │                   服务端把图记入 pending[sid]
       │                         ▼
       └──► 用户操作分叉：
            │
            ├─ 保存 ─────────► save/update 带 sid
            │                 服务端按正文认领 → 回收未认领
            │                 uploadSessionId 轮换为新 UUID
            │
            ├─ dirty:true→false ─► settleUploadSessionIfNeeded(html)
            │                      按正文结算（回收「上传又删」的 pending）
            │
            ├─ 切笔记 / 新建 ────► discardUploadSession() (async, Host http)
            │
            └─ 刷新 / 关页 ──────► flushUploadSessionOnPageHide(sid)
                                    → discardUploadSessionKeepalive(sid)
                                      keepalive fetch DELETE
```

### 3.2 关键决策

1. **会话 ID 存在 Store，不存编辑器**：编辑器在长文 / 短文 / 预览之间会反复卸载重建，`uploadSessionId` 放在 `LearningNotesStore` 才能在切换中存活。
2. **保存后立刻轮换 UUID**：保存过的图已经被认领到笔记，后续再上传的图应进入下一批 pending，避免「保存后又删」时把已认领的图误删。
3. **`pagehide` 而非 `visibilitychange`**：桌面端 Tauri 在失焦、粘贴、选文件时都会触发 `visibilitychange`，会误判为「离开」从而误删正文里的图；`pagehide` 只在真正刷新 / 关页时触发。
4. **`keepalive` fetch 直发**：`pagehide` 时浏览器会立刻卸页，基于 HostBridge 的 async http 会被掐断，因此用原生 `fetch(..., { keepalive: true })` 直发 `DELETE` 兜底。
5. **`dirty → clean` 时才 settle**：每次 `onChange` 都打 settle 接口太重；仅在「有改动 → 回到基线」（如上传后又撤销）时结算一次即可。
6. **`update` 返回 `{ id }` 而非 `Note`**：旧版返回完整 `Note` 但页面其实只用到 `id`，且 `toNote` 依赖的字段在 update 回包里不稳定；收敛为 `{ id }` 后调用方更直观。
7. **`uploadNoteImage` 失败返回 `null` 而非 `data:` URL**：失败时不插入 base64（避免正文里残留巨长字符串），让用户感知到上传失败并重试。

### 3.3 行为变化

| 场景 | 旧版 | 新版 |
|------|------|------|
| 上传图片 | 直接走 `fileToDataUrl` 或外部 `onUploadImage`，无 pending | 走 `NotesApi.uploadImage` 并带 `uploadSessionId` 记 pending |
| 上传后删除 + 保存 | 孤儿图残留 COS | 服务端按正文认领，未引用的 pending 自动回收 |
| 上传后删除 + 不保存 | 孤儿图残留 COS | dirty 回基线时 `settle`，或切笔记 / 关页时 `discard` |
| 刷新 / 关页 | 无清理 | `pagehide` keepalive `DELETE` 兜底 |
| `api.update` 返回类型 | `Note`（依赖 `toNote` 字段） | `{ id: string }` |

兼容性：本次改动是「前端 + 后端协同」型，需后端同时上线 `/upload-image` / `/upload-session/*` 接口；未上前端会因为没有 `onUploadImage` 注入而退化为 `fileToDataUrl`（base64 内联），不影响现有可用性。

```typescript
/**
 * 真正离页（刷新 / 关标签）时 keepalive discard。
 * ponytail: 不用 visibilitychange —— 桌面端失焦 / 粘贴 / 选文件也会 hidden，会误删正文里的图。
 * 切笔记 / 预览 / 新建由 discardUploadSession 处理，此处不做 cleanup flush。
 */
flushUploadSessionOnPageHide(sessionId: string): void {
	// 入参 sid 去空白；空串直接返回，避免误打接口
	const sid = sessionId.trim();
	// 没拿到 sid 不处理
	if (!sid) return;
	// 仅当传入 sid 仍是当前会话时才清空 Store 中的引用，
	// 避免在 sid 已被轮换（保存后）后误清新会话
	if (this.uploadSessionId === sid) this.uploadSessionId = null;
	// 直发 keepalive DELETE：浏览器卸页时 async Host http 会被掐断
	discardUploadSessionKeepalive(sid);
}

// 列表是否还能 loadMore：当前 list 长度小于 total
get hasMore(): boolean {
	// 还能分页时返回 true
	return this.list.length < this.total;
}
```

**变更摘要**：新增 `flushUploadSessionOnPageHide`：仅清 Store 引用 + 调 keepalive 直发 DELETE，不在卸页时尝试 async Host http。

```tsx
	// 记录「上一帧」dirty 状态：用于检测「dirty → clean」转换
	const wasDirty = dirtyRef.current;
	// 同步 ref
	dirtyRef.current = nextDirty;
	// 设置 state
	setDirty(nextDirty);
	// 仅在「有改动 → 回到基线」（如上传又删）时结算 pending，
	// 避免每次干净态 onChange 都打接口
	if (wasDirty && !nextDirty) {
		// 异步 settle：服务端按 HTML 认领 pending，未引用的回收
		void store.settleUploadSessionIfNeeded(html);
	}
}, [currentHtml, store]);
```

**变更摘要**：
1. 新增 `dirtyRef` 跟踪 ref，与 state `dirty` 同步。
2. `syncDirty` 在 `wasDirty && !nextDirty` 时调 `store.settleUploadSessionIfNeeded(html)`，结算「上传又删」的 pending。

## 5. 兼容性与影响

### 5.1 兼容性

- **前端独立可用**：未注入 `onUploadImage` 时 `RichEditor` 仍退化为 `fileToDataUrl`（base64 内联），不会因后端未升级而崩溃。
- **后端需协同**：服务端需提供 `POST /english-learning/notes/upload-image`、`DELETE /english-learning/notes/upload-session/:sid`、`POST /english-learning/notes/upload-session/:sid/settle`，并在 `save` / `update` 接收 `uploadSessionId` 时按正文认领 pending。
- **`update` 返回类型变化**：调用方（仅 `saveNote`）已同步改为读 `updated.id`，无外部消费者受影响。
- **`pagehide` keepalive**：依赖浏览器 `fetch keepalive` 与 `localStorage.token`；token key 与 Host http 一致。

### 5.2 风险与回归

| 风险 | 说明 | 建议 |
|------|------|------|
| 服务端 settle 接口异常 | settle 失败时 pending 不会被回收 | 依赖离页 discard + 服务端 TTL 兜底 |
| `crypto.randomUUID` 兼容性 | 老浏览器不支持 | 桌面端 Tauri2 / 现代 Web 均已支持；SSR 不会跑 |
| `pagehide` 在某些移动浏览器上不可靠 | 极少数情况下不触发 | 服务端 TTL 兜底（建议 24h） |
| 保存后轮换会话 ID | 若保存接口实际失败但前端已轮换 | 保存失败的 try/catch 不轮换（已实现：轮换在 runInAction 内，throw 时不执行） |

回归建议：
- [ ] 新建笔记 → 上传图 → 删除 → 不保存 → 切到另一篇：原 COS 上不应残留。
- [ ] 编辑已有笔记 → 上传图 → 保存：图应被认领到笔记。
- [ ] 编辑 → 上传图 → 刷新页面：刷新前应触发 keepalive DELETE。
- [ ] 编辑 → 上传图 → 删除 → 内容回到原样：dirty 由 true 转 false 时应触发 settle。
- [ ] 短文 / 长文两种编辑器都能上传图。
- [ ] 网络失败时编辑器不插入 base64。
