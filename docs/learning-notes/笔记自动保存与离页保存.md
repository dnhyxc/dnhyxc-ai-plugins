# 笔记自动保存与离页保存

## 1. 背景与目标

用户在学习笔记编辑过程中存在以下痛点：

- 切笔记/新建/预览前若忘记按 `Ctrl/⌘+S`，改动会丢失；
- 刷新页面、关闭标签、跳转 Host 路由时，异步 `saveNote()` 会被浏览器中断，正文无法落盘；
- 图片上传产生的 `uploadSessionId` 在无脏保存时仍需结算，避免 COS 孤儿图。

本次改动引入三层兜底：

1. **Store 层自动保存**：`openNew` / `openEdit` / `openPreview` 等离开当前编辑区前，调用 `autoSaveIfDirty` 静默保存；
2. **Host 路由离开**：插件 `deactivate()` 钩子触发自动保存；
3. **刷新/关页**：`pagehide` 事件通过 `fetch(..., { keepalive: true })` 完成保存或会话结算。

同时对 `saveNote()` 增加 `{ silent, auto }` 参数，区分「用户手动保存」与「系统自动保存」的 Toast 与列表刷新行为。

## 2. 改动范围

- `src/store/learningNotes.ts`：新增 `NoteEditorSnapshot` 类型、`registerEditorSnapshot`、`autoSaveIfDirty`、`leaveEditor`、`waitForSaving`、`flushNoteOnPageHide`；改造 `openNew` / `openPreview` / `openEdit` / `openEditById` / `saveNote` 签名与行为。
- `src/views/learning-notes/api.ts`：新增 `settleUploadSessionKeepalive` 与 `saveNoteKeepalive` 两个 keepalive 级别 API。
- `src/views/learning-notes/index.tsx`：注册编辑器快照回调、改造 `pagehide` 监听、`deactivate` 触发自动保存、清理若干 `useEffect`/`useCallback` 冗余依赖。
- `src/i18n/locales/zh-CN.ts`：新增 `learningNotes.toast.autoSaved`。
- `src/i18n/locales/en-US.ts`：新增 `learningNotes.toast.autoSaved`。

## 3. 实现思路

### 3.1 编辑器快照注入

页面层与 Store 层解耦：Store 不直接持有编辑器实例，而是由页面在 `useEffect` 中通过 `registerEditorSnapshot` 注入一个「读取当前快照」的回调。Store 在需要自动保存时调用该回调获得 `{ title, html, text, dirty }`。好处：

- 长文编辑器（`LargeNoteEditor`）与普通 `RichEditor` 统一为同一数据形状；
- Store 可在 `pagehide`、`deactivate` 等非 React 生命周期点读取数据。

### 3.2 离开编辑区统一入口

将 `openNew` / `openPreview` / `openEdit` 中原本散落的 `void this.discardUploadSession()` 收拢为私有方法 `leaveEditor()`：

1. 若正在保存中（`saving = true`），用 `waitForSaving()` 轮询至保存完成；
2. 否则调用 `autoSaveIfDirty({ silent: true })` 静默保存；
3. 最后 `await discardUploadSession()` 清理 pending 会话。

保证所有「离开当前编辑器」的路径都有一致的自动保存 + 会话回收行为。

### 3.3 saveNote() 支持静默/自动模式

新增可选参数 `opts?: { silent?: boolean; auto?: boolean }`：

- `silent`：不弹 `noSave` / `needContent` 等提示，列表刷新也改为 `void refreshList()` 不阻塞；
- `auto`：Toast 用 `learningNotes.toast.autoSaved`（已自动保存）替代 `saved`/`updated`，并跳过「空标题拦截」（自动保存时自动兜底为 `common.untitledNote`）。

### 3.4 pagehide keepalive 三级策略

`flushNoteOnPageHide()` 按优先级走三档：

1. **有脏数据 + 有正文内容** → 调 `saveNoteKeepalive()` 用 `keepalive` fetch 执行 `save` / `update`，并带 `uploadSessionId`；
2. **无脏保存但有会话与快照** → 调 `settleUploadSessionKeepalive()` 结算 pending（上传又删的图会被回收）；
3. **仅有会话无快照** → 调 `discardUploadSessionKeepalive()` 直接 discard。

注意不用 `visibilitychange`：桌面端失焦/粘贴/选文件时页面会变 `hidden`，会误删正文还在使用的图片。

### 4.2 `flushUploadSessionOnPageHide` → `flushNoteOnPageHide`（`src/store/learningNotes.ts`）

**对比范围**：`flushUploadSessionOnPageHide`（旧）替换为 `flushNoteOnPageHide`（新），同时引入 `autoSaveIfDirty` / `leaveEditor` / `waitForSaving` 三个私有/公开方法。

**改动前** · `src/store/learningNotes.ts`（基线，约 L102–L114）

```typescript
// 真正离页（刷新/关标签）时 keepalive discard。
// 不用 visibilitychange — 桌面端失焦/粘贴/选文件也会 hidden，会误删正文里的图。
// 切笔记/预览/新建由 discardUploadSession 处理，此处不做 cleanup flush。
flushUploadSessionOnPageHide(sessionId: string): void {
	// 先 trim 会话 id，避免前后空格

	if (this.uploadSessionId === sid) this.uploadSessionId = null;
```

```typescript
// 切笔记 / 新建 / 离页前：有改动则静默保存
async autoSaveIfDirty(opts?: { silent?: boolean }): Promise<boolean> {
	// 正在保存中或处于预览态：不重复保存/无需保存
	if (this.saving || this.preview) return false;
	// 调用页面注入的快照回调，读取当前编辑器内容
	const snap = this.getEditorSnapshot?.();
	// 编辑器未就绪或已卸载：无法自动保存
	if (!snap) return false;
	// 无改动（dirty=false）：只尝试结算 pending 上传会话（上传又删的图需要回收）
	if (!snap.dirty) {
		await this.settleUploadSessionIfNeeded(snap.html);
		return false;
	}
	// 有改动：走 saveNote，默认 silent=true 不打扰用户，并标记 auto=true 以触发「已自动保存」Toast
	return this.saveNote(
		{
			// 快照中的标题
			title: snap.title,
			// 快照中的富文本 HTML
			html: snap.html,
			// 快照中的纯文本
			text: snap.text,
			// 固定 dirty=true（外层已判断）
			dirty: true,
		},
		{ silent: opts?.silent ?? true, auto: true },
	);
}

// 离开编辑区：先自动保存，再清 pending 会话
private async leaveEditor(): Promise<void> {
	// 若已经在保存中，先等待保存完成再继续，避免并发写同一条笔记
	if (this.saving) {
		await this.waitForSaving();
	} else {
		// 非保存中：先尝试静默自动保存（无脏就结算会话）
		await this.autoSaveIfDirty({ silent: true });
	}
	// 保存完成后：清理当前上传会话（切笔记/新建/预览后新会话由后续动作生成）
	await this.discardUploadSession();
}

// 轮询等待 saving 变 false；切笔记时可能用户刚 Ctrl+S，需要等其落盘
private waitForSaving(): Promise<void> {
	// 瞬间已不在保存中：直接 resolve
	if (!this.saving) return Promise.resolve();
	// 否则用 requestAnimationFrame 每帧检查，避免阻塞主线程
	return new Promise((resolve) => {
		// 内部检查函数（递归）
		const check = () => {
			// saving=false 则 resolve，结束等待
			if (!this.saving) resolve();
			// 下一帧再检查
			else requestAnimationFrame(check);
		};
		// 启动第一轮检查
		check();
	});
}

// 刷新/关页：keepalive 保存或结算 pending（不用 visibilitychange）
flushNoteOnPageHide(): void {
	// 预览态无编辑器，无需处理
	if (this.preview) return;
	// 读当前编辑器快照（可能已被卸载：null）
	const snap = this.getEditorSnapshot?.();
	// 取当前上传会话 id（可能为 null）
	const sid = this.uploadSessionId;
	// 档 1：有脏数据且正文非空 → 用 keepalive fetch 真正保存笔记
	if (
		snap?.dirty &&
		hasNoteBodyContent(snap.html, snap.text)
	) {
		// keepalive 保存：id 为已有笔记则 update，否则 save；并带上上传会话 id 用于认领 pending 图
		saveNoteKeepalive({
			id: this.editingId,
			// 标题空时兜底用「未命名笔记」
			title: snap.title.trim() || this.t('common.untitledNote'),
			html: snap.html,
			uploadSessionId: sid,
		});
		// 立即清掉 Store 会话 id，避免后续重复操作
		this.uploadSessionId = null;
		return;
	}
	// 档 2：有会话 id 且有快照（非脏或正文空）→ keepalive 结算 pending（上传又删的图回收）
	if (sid && snap) {
		settleUploadSessionKeepalive(sid, snap.html);
		// 只有仍等于当前会话时才清空；极短窗口内可能已被新会话替换
		if (this.uploadSessionId === sid) this.uploadSessionId = null;
		return;
	}
	// 档 3：仅有会话 id（编辑器不可读）→ keepalive 直接 discard
	if (sid) {
		discardUploadSessionKeepalive(sid);
		// 同上述窗口保护
		if (this.uploadSessionId === sid) this.uploadSessionId = null;
	}
}
```

```typescript
	id?: string | null;
	// 笔记标题
	title: string;
	// 正文 HTML
	html: string;
	// 上传会话 id（用于认领 pending 图）
	uploadSessionId?: string | null;
}): void {
	// SSR/无 window 环境直接 return
	if (typeof window === 'undefined') return;
	// 从 localStorage 取 token
	const token = localStorage.getItem('token')?.trim();
	// 解析 API 域名
	const base = notesApiBaseUrl();
	// 缺少 token 或 base 时不执行
	if (!token || !base) return;
	// 标题 trim 后为空则用「未命名笔记」兜底
	const title = input.title.trim() || translateSync('common.untitledNote');
	// 构造保存 payload：先用 Record<string, string> 便于后续按需加字段
	const payload: Record<string, string> = {
		// 标题
		title,
		// 后端字段名 content，值为传入 html
		content: input.html,
	};
	// 取 trim 后的上传会话 id
	const sid = input.uploadSessionId?.trim();
	// 会话非空则并入 payload
	if (sid) payload.uploadSessionId = sid;
	// 统一请求头
	const headers = {
		// Bearer 鉴权
		Authorization: `Bearer ${token}`,
		// 请求体为 JSON
		'Content-Type': 'application/json',
	};
	// 取 trim 后的笔记 id（判断是更新还是新建）
	const id = input.id?.trim();
	// 有 id → PUT update
	if (id) {
		// keepalive fetch：更新指定笔记
		void fetch(`${base}${BASE}/update/${encodeURIComponent(id)}`, {
			// 方法：PUT
			method: 'PUT',
			// 统一请求头
			headers,
			// 把 id 也并入 body（后端 update 接口要求）
			body: JSON.stringify({ id, ...payload }),
			// keepalive：pagehide 下尽量发出
			keepalive: true,
		});
		// 提前 return，不落到下方 save
		return;
	}
	// 无 id → POST save 新建笔记
	void fetch(`${base}${BASE}/save`, {
		// 方法：POST
		method: 'POST',
		// 统一请求头
		headers,
		// 保存 payload
		body: JSON.stringify(payload),
		// keepalive：pagehide 下尽量发出
		keepalive: true,
	});
}

// 列表默认每页条数
export const NOTES_PAGE_SIZE = 20;
```

**变更摘要**：在原 `discardUploadSessionKeepalive` 下方新增两个 keepalive 级别函数：

- `settleUploadSessionKeepalive(sid, content)`：非脏离页时按正文回收被删除的 pending 图；
- `saveNoteKeepalive({ id?, title, html, uploadSessionId? })`：脏离页时直接用原生 fetch keepalive 走 `save`/`update` 接口。

两者都不依赖 HostBridge 的 `http.*`（`pagehide` 下 Host async API 会被浏览器中断），因此直接读 `localStorage.token` 并调 `fetch`。

## 5. 行为变化与兼容性

| 维度 | 变化 |
| --- | --- |
| 切笔记 / 新建 / 预览 | 原本 fire-and-forget 丢弃会话；现在先 `await` 自动保存再切换；若用户刚 `Ctrl+S` 则等待保存完成。对用户的直接感受是「切笔记不会丢内容」。 |
| `Ctrl/⌘+S` / 保存按钮 | 无功能差异；仅 Toast 文案保持 `已保存笔记` / `已更新笔记`。 |
| 刷新 / 关标签页 | 原本只丢弃 pending 图片；现在按「脏+有正文 → keepalive 保存；有会话无脏 → keepalive 结算；仅会话 → keepalive discard」三档处理。极端网络下仍可能被浏览器中断 keepalive，但比旧版异步 Host http 成功率高得多。 |
| 离开 Host 路由（插件 `deactivate`） | 原本只打日志；现在调用 `autoSaveIfDirty({ silent: true })`，若脏会静默保存（弹 `已自动保存` Toast）。 |
| 空标题拦截 | 手动保存仍拦截；自动保存场景（切笔记/关页）不拦截，自动用 `common.untitledNote` 兜底。 |
| Toast 策略 | 切笔记时 info 类 Toast（内容未变更、无正文、无标题、列表刷新）被 `silent` 抑制；成功 Toast 改为 `已自动保存` 不打扰用户。 |
| `useEffect` / `useCallback` deps | 移除了若干冗余 `store`/`t` 依赖；对运行时行为无影响，但减少回调/effect 重建次数。 |
| 导入新增 `learningNotesStore` 单例 | 仅用于 `deactivate` 静态方法中读单例；组件渲染仍走 `useStore()` 响应式。 |

## 6. 测试与回归建议

1. **切笔记自动保存**：编辑笔记 A 后点列表中的笔记 B（或点「新建」），回到列表时 A 应已落盘且显示最新标题。
2. **切预览自动保存**：编辑中不按保存直接点「预览」按钮；切换回编辑后内容仍存在。
3. **刷新/关页 keepalive 保存**：编辑中直接刷新浏览器（F5 / ⌘R）或关闭标签后重开；笔记列表应能看到最新修改。注意 `keepalive` 对请求体大小有上限（一般 64KB），超长笔记需测边界。
4. **Host 路由离开自动保存**：在插件 `deactivate` 触发点（切到其它路由）离开，列表应看到新内容。
5. **正在保存中切笔记**：按 `Ctrl/⌘+S` 后立刻切到另一篇，等待 saving 完成才切换，不出现并发 update 报错。
6. **非脏状态图片上传又删**：插入图片后立刻 `撤销`，dirty=false，切笔记或刷新应触发 settle，后端不保留该 pending 图。
7. **自动保存空标题**：正文有内容但标题空，切笔记或关页触发自动保存，标题自动变为「未命名笔记」。
8. **中英双语**：切换语言后，触发自动保存得到对应语言 Toast（`已自动保存` / `Auto-saved`）。
