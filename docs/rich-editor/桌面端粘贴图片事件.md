# 桌面端粘贴图片事件

## 1. 背景与目标

### 1.1 背景

`ImageUpload` 扩展通过 ProseMirror 的 `handlePaste` 拦截粘贴的图片文件，再走 `resolveSrcRef.current(file)` 上传或转 base64。在浏览器（Web 嵌入态）这套机制工作良好。

但桌面端基于 Tauri2，**Host 在原生层拦截了 Cmd+V**，Webview 里的 ProseMirror 根本收不到 `paste` 事件。结果是：用户在桌面端粘贴截图时，编辑器里什么都没发生，图片既不上传也不插入。

### 1.2 目标

为桌面端 Host 提供一个**自定义事件通道**：Host 拦截原生粘贴后，把解析出的 `File[]` 通过 `DESKTOP_PASTE_IMAGES_EVENT` 派发到编辑器 `dom`，由 `ImageUpload` 扩展复用既有 `insertImages` 流程完成上传与插入。

- 不引入新的依赖、不改动 `RichEditor` 组件签名。
- 与既有 `handlePaste` / `handleDrop` 共存：Web 端继续走 ProseMirror 原生粘贴，桌面端走自定义事件。
- 生命周期跟随 ProseMirror 插件：`view()` 绑定、`destroy()` 解绑，不会泄漏。

### 1.3 延伸阅读

- [富文本编辑器主文档](../rich-editor.md) — `ImageUpload` 扩展、`handlePaste` / `handleDrop`
- [笔记图片上传会话](../learning-notes/笔记图片上传会话.md) — 桌面端粘贴事件的下游消费者：`onUploadImage` + `uploadSessionId`

## 3. 实现思路

### 3.1 事件流

```
桌面端 Cmd+V
    │
    ▼
Host 原生层拦截 paste
    │
    │ 解析剪贴板得到 File[]
    ▼
editorView.dom.dispatchEvent(
    new CustomEvent('rich-editor:desktop-paste-images', {
        detail: { files: File[] },
    })
)
    │
    ▼
ImageUpload 扩展 view() 中的 onDesktopPaste 监听器
    │
    │ 1. filter(isImageFile) 过滤非图片
    │ 2. preventDefault + stopPropagation
    ▼
insertImages(editor, files, resolveSrcRef.current)
    │
    ▼
resolveSrcRef.current(file)
    │
    │  onUploadImage 存在 → 上传到 COS（带 uploadSessionId）
    │  否则 → fileToDataUrl（base64）
    ▼
editor.commands.setImage({ src })
```

### 3.2 关键决策

1. **复用 ProseMirror 插件 `view()` 钩子**：而不是在 `RichEditor` 组件里 `addEventListener`。这样事件监听与编辑器实例同生命周期，`destroy()` 时自动解绑，不会泄漏。
2. **绑在 `editorView.dom`**：与 `handlePaste` / `handleDrop` 在同一个 DOM 节点，便于 Host 定位；事件也不冒泡到外层（`stopPropagation`）。
3. **过滤 + 阻止默认**：`isImageFile` 过滤掉非图片（避免 Host 误把文本文件也派过来）；命中后 `preventDefault + stopPropagation`，避免后续 ProseMirror 默认处理把图片当文本插入。
4. **不替代 `handlePaste`**：Web 端 ProseMirror 仍走原生 paste；桌面端走事件。两套互不干扰，扩展自带「哪个先到哪个生效」的语义。
5. **常量导出**：`DESKTOP_PASTE_IMAGES_EVENT` 从 `image/index.ts` 重新导出，Host 侧可直接 `import` 而非硬编码字符串。
6. **不引入新 prop**：`RichEditor` 组件签名不变，Host 通过 DOM 派发事件即可，不破坏既有接入方。

### 3.3 行为变化

| 场景 | 旧版 | 新版 |
|------|------|------|
| Web 端粘贴截图 | `handlePaste` 拦截 → `insertImages` | 不变 |
| 桌面端 Tauri2 粘贴截图 | Host 拦截 paste，编辑器无反应 | Host 派发自定义事件 → `view()` 监听 → `insertImages` |
| 桌面端粘贴非图片 | — | `isImageFile` 过滤后不响应 |

兼容性：纯新增，不破坏既有 `handlePaste` / `handleDrop`；Host 不派发事件时扩展行为与旧版完全一致。

**改动后** · `src/components/design/RichEditor/image/ImageUpload.ts`（当前，约 L35–L64）

```typescript
// 返回 ProseMirror 插件数组
return [
	// imageUpload 插件：拦截 paste / drop，并监听桌面端粘贴事件
	new Plugin({
		// 插件 key
		key: new PluginKey('imageUpload'),
		// view() 钩子：插件挂载到 editorView 时触发；
		// 在这里注册 DOM 事件监听，destroy 时返回的 cleanup 会被调用
		view(editorView) {
			// 桌面端粘贴事件回调
			const onDesktopPaste = (e: Event) => {
				// 把 Event 断言为 CustomEvent，detail.files 为 File[]
				const ce = e as CustomEvent<{ files?: File[] }>;
				// 取出 files 并过滤为图片文件；非图片直接忽略
				const files = (ce.detail?.files ?? []).filter(isImageFile);
				// 没有图片文件：不处理，让别的监听器有机会
				if (!files.length) return;
				// 命中图片：阻止默认行为（避免后续 ProseMirror 把图当文本插）
				ce.preventDefault();
				// 停止冒泡（避免外层重复处理）
				ce.stopPropagation();
				// 复用 insertImages：走 resolveSrcRef.current 完成上传 / 插入
				void insertImages(editor, files, (f) => resolveSrcRef.current(f));
			};
			// 在 editorView.dom 上注册监听（与 handlePaste 同一个 DOM 节点）
			editorView.dom.addEventListener(
				DESKTOP_PASTE_IMAGES_EVENT,
				onDesktopPaste,
			);
			// 返回 cleanup 对象：插件销毁时调用
			return {
				// destroy：解绑事件，避免泄漏
				destroy() {
					editorView.dom.removeEventListener(
						DESKTOP_PASTE_IMAGES_EVENT,
						onDesktopPaste,
					);
				},
			};
		},
		// 插件 props：定义 handlePaste / handleDrop
		props: {
```

**变更摘要**：新增 `view(editorView)` 钩子，在 `editorView.dom` 上注册 `DESKTOP_PASTE_IMAGES_EVENT` 监听，命中后过滤图片、阻止默认、复用 `insertImages` 插入；`destroy()` 时解绑。

## 5. 兼容性与影响

### 5.1 兼容性

- **纯新增**：未删除或修改任何既有行为；Host 不派发事件时扩展表现与旧版一致。
- **与 `handlePaste` / `handleDrop` 共存**：三套机制互不干扰；命中顺序由 ProseMirror 与 DOM 事件触发顺序决定。
- **Host 侧依赖**：Host 需要在原生层解析剪贴板得到 `File[]` 并 `dispatchEvent`；未实现时桌面端粘贴仍无反应（与旧版一致）。

### 5.2 风险与回归

| 风险 | 说明 | 建议 |
|------|------|------|
| Host 派发 `detail.files` 为空 | `filter(isImageFile)` 后长度为 0，回调直接返回 | 不影响 |
| Host 派发非图片文件 | 被 `isImageFile` 过滤 | 不影响 |
| 事件名拼写不一致 | Host 硬编码字符串而非 import 常量 | 推荐 Host 从 `@dnhyxc-ai-plugins/RichEditor` import 常量 |
| `editorView.dom` 被替换 | 极少见；TipTap 不会替换 dom | destroy 时仍会解绑旧 dom 上的监听 |

回归建议：
- [ ] Web 端：粘贴截图 → 图正常插入（走 `handlePaste`）。
- [ ] 桌面端：Host 派发 `DESKTOP_PASTE_IMAGES_EVENT` → 图正常插入。
- [ ] 桌面端：派发空 `files` 数组 → 不报错、不插入。
- [ ] 切换 / 卸载编辑器 → 监听被解绑（可在 `destroy()` 内打日志验证）。
- [ ] 配合 [笔记图片上传会话](../learning-notes/笔记图片上传会话.md) 验证：桌面端粘贴 → 走 `onUploadImage` → 带 `uploadSessionId` 上传。
